# Arquitectura: seguridad y privacidad

ESTADO: Propuesto

## Principios

- minimización de datos;
- separación de datos de demostración y producción;
- autorización por rol;
- registro de auditoría;
- credenciales fuera del código;
- cifrado en tránsito y, cuando aplique, en reposo.

## Roles iniciales

- tripulación;
- despachador;
- coordinador;
- supervisor;
- administrador técnico;
- sistema o servicio interno.

## Datos del prototipo

No pueden contener:

- nombres de afiliados;
- documentos;
- teléfonos personales;
- datos clínicos identificables;
- direcciones exactas;
- costos reales no autorizados;
- volúmenes operativos reales no aprobados.

## Ubicación

- consentimiento y permisos visibles en la app;
- precisión limitada o generalizada según necesidad;
- no retener historial innecesario;
- acceso al mapa limitado por rol;
- borrado o retención conforme a una política aprobada.

## Auditoría

Registrar al menos:

- recomendación generada;
- modelo y versión usados;
- opción seleccionada;
- usuario o sistema que confirmó;
- cambios posteriores;
- motivo de rechazo o modificación.

## Cumplimiento

El prototipo se debe diseñar considerando Ley 1581 de 2012 y normativa aplicable a datos de salud. Las decisiones legales definitivas requieren validación de la organización y asesoría jurídica.
